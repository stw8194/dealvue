# DealVue 재검증 — 2026-11-01

## 결론

로컬 수정본에서 예약 초기 로딩, 드레스룸 새로고침, 최근 본 매장 계정 분리 회귀 검증을 통과했다. 공개 사이트의 이전 예약 버전과 비www 도메인 DNS 문제는 남아 있다. 따라서 공개 전시 운영 준비가 모두 끝났다고 판단하지 않는다.

이번에는 앱 코드·DB·인증·도메인 설정을 변경하거나 커밋·푸시·배포하지 않았다. 기존 소스 상태를 검사하고 테스트 보고서만 추가했다.

- 실제 Safari 데스크톱 및 반응형 디자인 390×844 검사.
- `npm run lint`: 통과.

- `git diff --check`: 통과.

### 자동 검증 7종 — 모두 통과

1. `scripts/check-account-isolation.mjs`: 실제 Zustand + 임시 IndexedDB로 계정 A/B/게스트의 포인트·출석·찜·최근 본 매장·외형·소유 의상·코디·룰렛 상태 분리. 계정 전환 중 쓰기 및 지연 읽기 검사.
2. `scripts/check-booking-response.mjs`: 전송 모의 객체로 저장 후 응답 유실, 동일 요청 재확인, 새로고침에 해당하는 보류 요청 복원, 계정 구분, 확정 거절/게이트웨이 불확실성 구분, local 로그아웃 인자 검사.
3. `scripts/check-shared-query.mjs`: 요청 공유, 느린 응답 중 중복 방지, 변경 후 무효화, 숨긴 탭 정지, 재개, 오류 백오프 및 복구.
4. `scripts/check-catalog-traffic.mjs`: 메타데이터 캐시, 요청 공유, 수량 갱신, 오류 재시도, 서울 자정 갱신.
5. `scripts/check-consumer-booking-db.mjs`: 격리 PGlite DB. 75개 실제 원본 시술, 할인 시작 경계, 시술 전체 점유, 인접 경계, 다른 담당자, 변경 실패 원상 유지, 취소 해제, 요청 ID 멱등성, 패키지 롤백, RLS 및 기존 읽기 최적화 결과 일치. 잠금 경합·처리량 측정은 아님.
6. `scripts/check-community-db.mjs`: 격리 DB. 스키마 재실행, 시드, 조회·작성자 권한, 댓글/좋아요/중복 처리, 필터, 삭제 상태, 업로드 경로 분리.
7. `scripts/check-coupon-and-legacy-cache.mjs`: 비로그인 쿠폰 거절, 계정 RPC 성공·실패·재시도, 레거시 캐시 정리 범위.

추가 임시 검사 `/private/tmp/dealvue-reservation-loading-check.mjs`: 실제 useReservations 훅을 제어된 인증/조회 스냅샷으로 실행. 인증 미완료, 해당 계정 첫 조회 대기, 계정 변경 시 이전 예약 미노출, 조회 실패, 비로그인 상태를 확인했다. 실제 네트워크/React DOM 통합 테스트와는 구분한다.

## 실제 브라우저 확인

### 예약 초기 로딩 — 통과

기존 서버 테스트 예약 #7 상세를 연 뒤 새로고침했다. 처음에는 ‘예약 정보를 불러오는 중입니다’를 표시하고 조회 후 취소된 예약 상세가 정상 복원됐다. 검사한 시점에서 초기 ‘예약을 찾을 수 없습니다’는 재현되지 않았다. 프레임 단위 화면 녹화로 모든 순간을 검사한 것은 아니며, 위 훅 상태 검사로 초기 분기도 함께 확인했다.

### 드레스룸 — 통과

테스트 계정의 원래 외형은 코코 단발·체스넛이었다.

1. 벨벳 웨이브·로즈 핑크로 변경하고 ‘내 모습 적용하기’를 눌러 저장.
2. 드레스룸 주소에서 브라우저 새로고침.
3. 얼굴·헤어 탭을 열어 저장한 웨이브·로즈 핑크 선택 상태 확인.
4. 변경 전 ‘지금 나의 얼굴과 헤어’ 버튼이 비활성인 것 확인.
5. 코코 단발·체스넛으로 복구하고 저장. 적용 버튼 비활성 확인.

실제 테스트 계정의 로컬 외형만 임시 변경 후 원복했다. 일반 사용자 외형이나 아바타 이미지 파일은 변경하지 않았다.

### 시간별 할인·정상가 — 통과

프로덕션 빌드의 모바일 예약 화면에서 벨루니크 ‘증명사진 메이크업’ 검사:

- 할인 방문 시간 13:00~13:40, 소요 60분.
- 13:30 선택: 타임딜 특가 35,000원.
- 14:00 선택: 정상가 예약 50,000원으로 표시 및 요약 금액 전환.
- 오전/오후, 시간 버튼, 담당자 선택 표시 확인.
- 예약 단계 결제수단 없음, 방문 시 결제 안내 확인.
- 확정 예약은 새로 만들지 않았다.

### 취소 후 결과 화면 — 통과

이미 취소된 서버 예약 #7의 `/booking/complete/7`을 직접 열었다. ‘예약이 완료되었습니다’ 대신 ‘취소된 예약입니다’를 표시했다. 응답 유실부터 취소까지를 실제 네트워크 장애로 연속 재현한 것은 아니며, 기존 취소 예약의 결과 화면 검사다.

## 공개 사이트 — 해결 필요

### 이전 배포 번들

읽기 전용 HTTP 조회 결과:

- `https://www.dealvues.com/`: HTTP 200, Vercel 로그인으로 이동하지 않음.
- 주 번들 `/assets/index-pF8AnP-l.js`.
- 주 번들에 `consumer_create_booking` 문자열 없음, `dealvue-ledger` 문자열 있음.
- 로컬 수정본과 공개 사이트의 배포 차이가 남아 있다는 기존 보고와 일치한다.

이번에는 공개 사이트에서 예약을 생성하지 않았다. 공개 앱의 런타임 저장 동작 자체를 새로 재현한 결과가 아니라, 배포 산출물 대조 결과다. 현재 HEAD는 8892892이며 서버 예약 관련 변경은 여전히 작업 트리에 있다. 공개 사이트가 최신 서버 예약 코드로 운영된다고 판단할 근거가 없다.

### 비www 주소

`https://dealvues.com` 조회는 `ENOTFOUND`로 실패했다. DNS 해석이 실패한 상태에서는 HTTP 리디렉션까지 도달하지 못한다. DNS 레코드·Vercel 도메인 연결·인증서·정규 주소 리디렉션을 배포 작업 때 점검해야 한다. 이번에는 수정하지 않았다.

## 남은 범위와 한계

- 리오벨라 ‘데이트 맞춤 메이크업’의 원본 영업시간/할인 시작/90분 소요 충돌은 그대로다. 75개 원본 검사에서 이 한 항목은 할인 가능한 영업시간 후보가 없다.
- 최근 본 매장 분리는 격리 저장소 전환 검사 통과. 실제 브라우저에서 두 계정을 새로 로그인해 왕복한 검사는 이번에 하지 않았다.
- 실휴대폰 두 대의 동시 예약, 운영 DB의 다중 연결 잠금 경합, 50/100/200명 부하 테스트는 이번에 하지 않았다.
- 카카오·구글 OAuth 실제 왕복과 운영 Redirect URL 설정 검사는 이번 범위에서 새로 수행하지 않았다.
- 앱 전체 메뉴를 처음부터 끝까지 다시 순회한 감사가 아니라, 최근 수정 항목과 핵심 예약/계정 회귀 검사다.
- 테스트 자격증명 파일의 TextEdit 열기는 자동 승인 검토에서 구체적 접근 승인 부족 사유로 거절됐다. 파일을 열지 않았고, 기존 테스트 계정 로그인 세션으로 브라우저 검증을 완료했다.
